# 图像加工与制作助手

新版程序：`release/processing-organize-client/win-unpacked/素材工坊.exe`（包含保存整理与尺寸输入修复）。双击工作区的 `启动示例工坊.cmd` 使用已有示例库。若旧版工坊正在运行，先关闭旧版，再从脚本启动新版。

## 进入编辑器

- 左侧「图像加工」→「添加图片」，通过系统文件选择器导入一张或多张图片。
- 素材库选择图片后，右键「加工图片…」。多选图片共用一套配方，逐张保存结果。
- 图片查看器右键「加工图片…」。
- 「AI 生成」的候选卡片点击「加工」。
- 加工候选点击「从此结果继续」，以该结果作为新的输入；保留之前的加工链。

界面左侧配置工具，中间预览和比较，右侧管理步骤、配方、助手和历史。原素材和候选不会被覆盖。加工结果自动保存到历史，在「保存与整理」检查建议并确认后成为衍生素材记录。

## 基础工具

工具全部通过本机 Sharp/libvips 执行：尺寸缩放、自由裁剪及 1:1／16:9／3:4 裁剪、90°／180°／270° 旋转、水平／垂直翻转、透明边缘裁切、画布补边、亮度／对比度／饱和度／色相／着色、锐化和基础中值降噪。

缩放有等比补边、等比裁切和拉伸三种适配方式；像素画请选择「最近邻」。透明边缘裁切只检查透明通道，不会把纯色背景误认为空白。补边可指定透明或十六进制颜色。

选择工具并设置参数，再点击「添加步骤」。点击右侧已添加的步骤可修改参数，点击「更新步骤」应用修改。「撤销」「重做」「恢复原图」操作配方，不删除原件。可以把步骤保存为命名配方，并应用于多张输入。

尺寸输入支持先清空再输入，清空时保留上次有效参数，不立即回填 0。加工窗口点击背景或从输入框拖到背景松开不会关闭；关闭请使用右上角关闭按钮或 Escape。

预览和最终输出均从完整输入按顺序执行。EXIF 方向在建立工作图时归一化，裁剪坐标和蒙版尺寸以该工作图的实际像素为准。首期处理静态栅格图；BMP、TGA、PSD 合成图等使用工坊现有解码器。动图或多页图片会要求选择从 0 开始的单帧／单页。

单张输入上限 64 MiB、32 MP；单套配方最多 20 步、100 张输入。结果和步骤中间图均为无损 PNG，保留透明通道。完整工作图、候选和蒙版存入素材库 `processing/`，预览缓存清理不会删除它们。

## AI 加工

在「模型与工作流连接」配置现有 Codex、OpenAI／兼容 Images 服务或 RunningHub。密钥由 Electron 主进程加密保存在应用配置中，不进入加工记录、备份和素材包。

AI 用途包括局部修改、语义改色、去背景、修复与增强、超分。连接必须具备参考图能力；绘制局部蒙版还需要当前连接声明支持蒙版。缺少能力会明确提示，工坊不会自动更换服务。Codex 当前提供参考图编辑和助手；原生蒙版能力按连接描述开放。

RunningHub 使用已有工作流 API。添加工作流 ID／链接、读取或导入 API JSON、映射输入图片字段，再在连接设置勾选「加工用途」。超分必须选择已标记超分用途的 RunningHub 专用工作流。可编辑已映射的自定义参数；未指定参数沿用工作流默认值。

局部修改使用「绘制局部蒙版」：画笔选择需要修改的位置，擦除恢复保留区域，支持撤销和清空。保存蒙版后添加 AI 步骤。改变前置步骤会清除受影响的蒙版并提示重画；后台也会验证工作图哈希。

本地合成保证蒙版保留区的 RGBA 像素不变。若 AI 返回尺寸和工作图／蒙版不匹配，停止自动合成，保留云端原候选供检查；可到「AI 生成」历史查看。去背景结果若没有透明像素也会停止，并保留原候选。

「检查整套方案」显示输入数量、步骤、目标规格、图像调用次数、上限、模型和费用。未配置价格时显示未知。检查后点击「启动整套方案」，后台执行并逐步保留候选。

## 制作助手

输入需求并选择助手可使用的图像连接与模型，也可选择只用本地工具。点击「让助手提出方案」。此时只消耗 Codex 分析额度，不执行图片生成或加工；检查、修改方案后点击启动。

启动后工坊执行经过校验的工具行动，并将实际图片、尺寸、透明度和比较结果送回助手检查。每套方案最多八个分析回合，默认最多一次额外修正；额外 AI 修正包含在显示的图像调用上限内。新增步骤、更换服务、进一步修正或超限会进入需调整状态，已完成结果继续保留。

优先使用 Codex App Server stdio 的连续会话、图片输入与进度。初始化接口不兼容时使用同一 Codex 连接的 `exec --json` 结构化回合，并保留本地会话记录。已发送分析回合后若连接丢失，不自动再调用一次。助手只能提出工坊校验的行动，不能自行调用 shell、外部服务或无限循环生成。

## 比较、历史、入库和交付

勾选候选可放大预览，选择「并排比较」或「拖动对比」。勾选两个结果时可并排比较两个结果；单个结果可与输入比较。「从此结果继续」创建新加工输入。加工历史可恢复当时的输入、配方与助手记录，再检查方案后重新启动。

每张输入的最终结果默认选中，中间步骤可手动勾选。点击「保存与整理」自动识别内容，检查中文标题、英文文件名、分类、标签和推荐位置，可逐项或批量修改，再点击「确认保存并加入」。允许仅入库或加入多个项目、手动收藏集；智能收藏集按实际规则自动匹配。重复点击复用同一入库结果，后续保存仅补充归属。衍生素材继承原来源和许可信息，追加输入哈希、步骤顺序、参数、工具版本、父结果及 AI 来源。完整说明见 [加工结果保存与整理](加工结果保存与整理.md)。

入库后通过现有项目、Godot／通用导出及标准 ZIP 流程交付。完整备份、恢复、清单重建和标准包再导入会保留加工信息。恢复到新库后不重放旧机器正在运行的加工或助手任务，先检查记录；应用连接和密钥需要在当前应用中配置。

全局后台执行并发为二，Codex 分析、检查和生图合计最多一个任务。父任务协调子步骤，不占执行槽。暂停在步骤边界等待，已经提交的云端调用无法暂停。取消按连接能力执行，并显示远端能否取消；已完成步骤保留。重试只处理失败项目，从失败步骤继续。明确重试新提交会增加记录中的调用数；查询已有远端任务和重新下载结果不会增加图像调用。

## 验证与边界

本机已实测 Codex App Server 连续方案／检查流程，以及 `exec --json` 回退；没有为该验收调用付费图片模型。Images 编辑接口、蒙版合成和 RunningHub 任务恢复通过模拟服务与恢复测试，真实 OpenAI 和 RunningHub 加工仍需要已授权密钥与用户工作流，当前不标记为真实云端验收通过。

首期不包含本地 AI 模型安装、图层、节点编辑器或视频加工。历史恢复保证输入和参数记录，云端再次生成不保证像素完全相同。
